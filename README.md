## Логика расчёта платежей с учётом механизмов удержания

Анализируем все платежи клиентов за 01.11–18.11.2026. Прежняя разбивка по банкам, размерам платежей, новым и действующим клиентам, вкладам, НС и ДВС сохраняется. Дополнительно каждому клиенту присваиваются признаки потенциального и фактического получения предложения на удержание.

### 1. Потенциальное получение предложения (`eligible_group`)

Рассматриваются клиенты розничного сегмента, совершившие исходящий СБП-перевод самому себе на сумму от 1 млн рублей.

- SMS — клиент совершил подходящий перевод и не получал СМС в предыдущие шесть календарных дней. Потенциальное окно составляет семь дней начиная с даты перевода.
- Push — клиент совершил подходящий перевод в день закрытия вклада или в течение следующих двух дней.
- SMS + Push — клиент соответствовал условиям обоих механизмов за рассматриваемый период.
- Нет — клиент не соответствовал расчётным условиям.

### 2. Фактическое получение предложения (`fact_group`)

На основании реестра СМС и пушей `VW_promocode_FL_list` клиенты делятся на четыре группы: SMS, Push, SMS + Push, Нет.

Учитываются также СМС с 26 октября и пуши с 30 октября, поскольку предложения могли оставаться актуальными в начале ноября.

### 3. Дополнительные признаки платежей

| Поле               | Описание                                                                                        |
| ------------------ | ----------------------------------------------------------------------------------------------- |
| `trigger_payment`  | Платёж соответствует условиям запуска механизма удержания                                       |
| `sms_window`       | Платёж совершён внутри потенциального семидневного окна СМС                                     |
| `push_window`      | Платёж совершён между подходящим переводом и окончанием двухдневного окна после закрытия вклада |
| `sms_offer_window` | Платёж совершён в течение семи дней начиная с даты фактической отправки СМС                     |
| `push_view_day`    | В день платежа клиент просматривал пуш-шторку                                                   |
| `push_viewed_ever` | Клиент хотя бы раз просматривал пуш-шторку в учитываемом периоде                                |

### 4. Какие платежи относятся к каждой группе

Все платежи клиента за рассматриваемый период, а не только переводы, запустившие механизм удержания.

Например, если клиент перевёл себе 1,5 млн рублей, получил СМС, затем вывел ещё 200 тыс. рублей и впоследствии вернул 500 тыс. рублей, все эти операции будут относиться к группе клиентов, получивших СМС.

Клиенты, не участвовавшие в механизмах удержания, также остаются в общей статистике. Таким образом, добавление новых признаков не должно менять суммарные объёмы платежей.

### 5. Ограничения методологии

- Потенциальное получение предложения определяется без проверки версии приложения клиента.
- Для пуша не учитывается прекращение действия предложения после открытия нового вклада.
- Факт получения пуша определяется по созданию оффера, факт просмотра учитывается отдельно.
- Сопоставление событий выполняется на уровне календарного дня, без учёта точного времени операции.

Поэтому потенциальное получение предложения следует интерпретировать как соответствие известным бизнес-условиям, а не как гарантированную необходимость отправки СМС или показа шторки.
